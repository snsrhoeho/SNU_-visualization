데이터 정제후 추가 수정사항 반영 요청

기존 `데이터 셋 적용 프롬프트.txt`의 기준은 유지하되, 아래 항목은 이번 추가 수정사항을 최종 기준으로 적용해주세요.
기존 프롬프트와 아래 내용이 충돌하는 경우에는 아래 추가 수정사항을 우선해주세요.

1. 휴식·운동 카테고리 수정

- `1-2. 놀이터.csv`를 놀이터 데이터로 사용해주세요.
- 기존 “놀이체험시설” 명칭은 홈페이지의 카테고리명, 필터명 및 내부 분류명에서 사용하지 마세요.
- `1-3. 헬스장.csv`에는 기존 체육시설과 헬스장 데이터가 통합되어 있습니다.
- `1-3. 헬스장.csv`의 모든 행을 “헬스장”으로 표시해주세요.
- 이전의 `1-3. 체육시설.csv`와 `1-4. 헬스장.csv`를 별도로 읽거나 중복 반영하지 마세요.
- 휴식·운동의 최종 세부 유형은 공원, 놀이터, 헬스장입니다.

2. 카페 분류 수정

- 카페 CSV의 `세부분류` 값은 `일반카페`와 `테마카페`만 사용합니다.
- 이전에 `기타`였던 값은 최종 CSV에서 모두 `테마카페`로 변경되었습니다.
- 홈페이지에서 “기타” 카페 유형을 만들거나 별도의 기준으로 다시 분류하지 마세요.
- 카페 CSV에 저장된 최종 `세부분류` 값을 그대로 사용해주세요.

3. 경찰관서 좌표 반영

- `9_siheung_경찰관서.csv`에 추가된 `위도`, `경도` 컬럼을 사용해주세요.
- 경찰서·지구대·파출소는 행정구역 중심점이 아니라 각 행의 위도·경도를 사용해 개별 점 마커로 표시해주세요.
- `위도`는 latitude, `경도`는 longitude로 연결하며 순서를 바꾸지 마세요.

4. CCTV 지도 표시 수정

- `9_siheung_CCTV.csv`의 `WGS84위도`, `WGS84경도`를 사용해 각 CCTV를 실제 좌표 기반 점으로 처리해주세요.
- CCTV를 행정동·생활권 단위 원, 반경, 밀집도 구역 또는 폴리곤 음영으로 대체하지 마세요.
- 기존 코드에서 CCTV에 `density_only`, `aggregate_only` 또는 유사한 구역 집계 전용 설정이 적용되어 있다면 제거하거나 `false`로 변경해주세요.
- CCTV 점이 지도에 표시되도록 `map_visible` 또는 해당 프로젝트의 동일 역할 설정을 활성화해주세요.
- 약 2,000개의 점 때문에 지도 성능이 저하될 경우 좌표 기반 마커 클러스터링을 사용할 수 있습니다.
- 클러스터는 개별 CCTV 좌표를 바탕으로 생성되어야 하며, 지도를 확대하면 실제 CCTV 점 마커가 나타나야 합니다.
- CCTV 마커 클릭 시 가능하면 설치목적, 주소, 카메라대수 등 해당 CSV 행의 정보를 보여주세요.

5. 최종 검증

- 휴식·운동 필터에는 공원, 놀이터, 헬스장만 나타나야 합니다.
- 카페 필터에는 일반카페와 테마카페만 나타나야 하며 “기타”는 없어야 합니다.
- 경찰관서와 CCTV는 CSV의 실제 위도·경도에 따라 개별 점 또는 좌표 기반 클러스터로 표시되어야 합니다.
- 삭제된 이전 파일명이나 기존 데이터 소스를 코드에서 계속 참조하지 않는지 확인해주세요.
- 같은 장소가 중복 표시되지 않는지 확인해주세요.
